# 角色与地图比例校正（0.5.0）

日期：2026-11-03（Asia/Shanghai）

地图版本：`core-pixel-3d-0.5.0`

## 问题与处理

旧角色将 16×32 贴图直接作为逻辑显示尺寸。地图室外每投影单位只有 4px，室内为 6px，角色却没有随场景尺度变化，因此明显偏大，室内外还表示不同的真实体型。原先 64px/s 移动和固定 5px 碰撞半径也存在同样的问题。

本次按「真实比例」的新要求，以米为单位配置人体与操作参数，再换算每个场景的逻辑像素。16×32 仍可作为绘制贴图的分辨率，不再决定角色在地图中的大小；没有使用最小显示尺寸把角色重新放大。相机缩放同时放大地图与角色，保持两者比例。

## 地图地面尺寸

EPSG:3857 的投影坐标不能直接当作地面米数。根据校园固定原点 Y=2618750 和球面 Web Mercator 公式，参考纬度约为 22.89024°。局部地面比例采用 `米／投影单位 = cos(纬度)`，约为 0.9212517；因此室外约 4.34192px/m，室内约 6.51288px/m。公式来源为 [PROJ Web Mercator 文档](https://proj.org/en/stable/operations/projections/webmerc.html)，局部比例由其球面投影公式推导。

这是对当前地图坐标的局部地面比例近似，不是重新测绘校园。建筑几何和原有投影保持不变。

| 项目                         |              室外 |                      室内 |
| ---------------------------- | ----------------: | ------------------------: |
| 像素／投影单位               |                 4 |                         6 |
| 逻辑像素／地面米             |           4.34192 |                   6.51288 |
| 当前室外地图含边距的地面范围 | 约 416.41×401.67m | 按各实际 F1／翼楼分别计算 |

默认镜头按可玩画布计算。桌面人物占画面高度约 8.75%，小屏横向约 7.5%。进出建筑或调整窗口时重新换算相机倍率。

## 人体尺寸与显示

默认身高 1.75m、体宽 0.50m、地面纵深 0.28m。这些是可调整的角色设计值，不是对校园人员的实测统计。

沿用建筑图像的 2.5D 高度投影系数 0.74。

```text
显示宽度 = 体宽 × 场景像素／米
显示高度 =（身高 × 0.74 + 地面纵深）× 场景像素／米
```

| 项目                           | 室外逻辑像素 | 室内逻辑像素 |
| ------------------------------ | -----------: | -----------: |
| 角色宽度                       |        2.171 |        3.256 |
| 角色显示高度（含地面纵深投影） |        6.839 |        10.258 |
| 脚底碰撞半径（0.22m）          |        0.955 |        1.433 |
| 基础速度（2.8m/s）             |   12.157px/s |   18.236px/s |
| 交互半径（1.5m）               |        6.513 |        9.769 |

基础速度由上一版 1.4m/s 提高一倍至 2.8m/s，按住左／右 Shift 时进一步提高至 5.6m/s。室外奔跑约 24.315px/s，室内约 36.472px/s；松开 Shift、失焦或打开面板会清除奔跑输入。

在 1088×746 的桌面游戏画布中，默认人物约高 65 CSS px。室内外用同一个屏幕占比，脚底碰撞、走速和真实交互距离仍使用当前场景的米制比例。每逻辑像素烘焙为 3×3 个美术像素，家具、墙面和地板纹理均在这个密度下采样。

取景参考了两张官方实机图。在《星露谷物语》的农场图中，站立人物约高 54–58 像素，画面高 576 像素；在《风来之国》的营地画面中，中央成年人物约占画高的 13–14%。两项均为按画面估读的比例。校园默认视野留出更多走廊空间，便于看到门口和交界处。[农场画面](https://www.stardewvalley.net/wp-content/uploads/2016/02/StardewValley_4_1-1024x576.png) · [营地画面](https://eastwardgame.com/wp-content/uploads/2023/10/eastward-features-5.jpg)

宝箱也按 0.80m 宽、0.55m 高、0.45m 深同步缩放，避免角色校正后宝箱仍显得巨大。编号、探索标记和入口提示属于界面注释，不作为实际建筑或物件体积。

碰撞网格仍为 4px，局部边缘存在栅格近似；脚底碰撞体已按米换算，不再使用旧的 5px 大圆。构建时按各场景真实碰撞半径重新验证点位可达性。屋顶投影可能覆盖 F1 轮廓之外的地面，因此角色被屋顶像素遮挡时也会触发淡化。

## 配置与验证

人体、步速、交互及宝箱米制参数位于 `content/map-config.json`。换算由 `src/shared/scale.ts` 统一计算，写入每个场景的 `units` 和 `player`；报告的 `scaleAudit` 记录各场景尺寸、比例和物理参数。

单元测试检查赤道、60° 纬度与校园纬度的投影比例，以及室内外相同人体尺寸、速度、范围和地图地面面积。浏览器测试读取 Phaser 实际显示宽高，验证它们对应 0.50m 体宽与 1.75m 身高，并在新步速与碰撞体下沿真实 C2 平面完成往返。
